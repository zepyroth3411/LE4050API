# TEST-002 — CreateAccessToken

## Test Information

**Test ID:** TEST-002  
**Endpoint:** `CreateAccessToken`  
**Method:** `POST`  
**API Version:** v3  
**Environment:** Production  
**Status:** VALIDATED / PASS  

---

## 1. Objective

Validate the exchange of a previously generated authorization code (`AuthCode`) for an access token and refresh token.

The resulting `AccessToken` will be used to authenticate subsequent API requests.

---

## 2. Endpoint

```http
POST https://app.m2mservices.com/CommonAdministrationService/api/v3/CreateAccessToken
```

---

## 3. Documented Behavior

According to the API specification:

- the request receives the `AuthCode` generated by `CreateAuthorizationCode`;
- the authorization code is intended for one-time use;
- the response returns an `AccessToken`;
- the response returns a `RefreshToken`;
- the response returns an `ExpirationDate`;
- the `AccessToken` is used in the `M2MOAuth2Token` header for subsequent authenticated requests;
- the documented access-token lifetime is 60 minutes;
- an unknown or previously used authorization code returns error `-2005`;
- `TwoFactorAuthCode` is required only when the previous authentication step indicated that two-factor authentication was required.

---

## 4. Request Schema

The API defines the following request fields:

- `AuthCode`
- `TwoFactorAuthCode`
- `PhoneID`
- `PhoneDescription`
- `CompanyBundleId`

For this validation, only the minimum required field was sent because the account did not require two-factor authentication.

---

## 8. Interpretation

The `AuthCode` generated during TEST-001 was successfully exchanged for an authenticated API session.

The returned `AccessToken` can now be used to authenticate protected API endpoints through the following HTTP header:

```http
M2MOAuth2Token: <ACCESS_TOKEN>
```

The returned `RefreshToken` is intended to obtain a new access token after expiration without requiring the user to authenticate again.

`AdminLogin: false` remained consistent with the end-user authentication context established during TEST-001.
